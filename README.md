# 문항맵

모의고사 PDF를 **문항별로 나누고, 원문 전체를 캡처하고, 2022 개정 교육과정 성취기준 후보를 연결해 DOCX/HWPX로 내보내는** 교사용 도구입니다. 여러 시험지의 문항을 로컬 문제함에 모아 함께 내보낼 수 있습니다.

현재 버전은 `0.5.1`입니다. 기본 사용 방식은 **내 컴퓨터의 로컬 서버 + 웹 브라우저**입니다. 문항맵용 DMG/EXE를 설치하거나 ChatGPT에 로그인할 필요는 없지만, 실행 환경인 Node.js는 필요합니다. HTML 파일을 더블클릭하는 `file://` 방식은 지원하지 않습니다.

> 자동 추출·AI 판독·성취기준 추천은 초안입니다. 교사가 원문과 비교하고 수정한 뒤 사용하세요. API를 연결하면 판독 대상 문항 이미지와 텍스트가 선택한 공급자에게 전송되며 비용이 발생할 수 있습니다.

이 저장소는 공개되어 있고 문항맵 자체 코드는 MIT 라이선스입니다. 이미 만들어진 실행 폴더는 [Releases](https://github.com/RuneDaeg/munhang-map/releases)에서 내려받을 수 있으며, Node.js만 설치하면 소스 없이 바로 쓸 수 있습니다. 저장소 공개와 로컬 앱의 로그인 여부는 별개이고, 시험지·문항의 저작권과 재배포 권한도 소스 공개와 별개입니다.

## 1. 준비와 처음 실행하기

### 1-1. 실행 환경 준비

1. [Node.js 공식 다운로드](https://nodejs.org/en/download)에서 **22.13 이상인 지원 중 LTS 버전**을 설치합니다. Apple Silicon Mac은 ARM64, Intel Mac은 x64 등 자신의 컴퓨터에 맞는 설치 파일을 선택합니다.
2. 설치 후 터미널을 새로 엽니다. Mac은 **터미널**, Windows는 **명령 프롬프트(cmd)**를 사용할 수 있습니다.
3. 아래 명령을 한 줄씩 실행합니다. Node.js와 함께 제공되는 npm으로 pnpm 10을 설치합니다. 다른 설치 방법은 [pnpm 10 공식 설치 안내](https://pnpm.io/10.x/installation)를 참고하세요.

```bash
node --version
npm --version
npm install -g pnpm@latest-10
pnpm --version
```

마지막 결과가 `10.x.x`인지 확인합니다. Git으로 내려받으려면 Git도 필요하지만, ZIP 다운로드 방식은 Git 없이 가능합니다. 첫 의존성 설치에는 인터넷과 충분한 저장 공간이 필요합니다. 소스에는 선택 사항인 Electron 앱 의존성도 포함되어 설치가 오래 걸릴 수 있습니다.

### 1-2. 소스 내려받기

**Git을 사용하지 않는 방법:** [저장소](https://github.com/RuneDaeg/munhang-map)의 **Code → Download ZIP**을 선택해 압축을 완전히 풉니다. 압축 파일 내부에서 실행하지 마세요. 압축을 푼 `munhang-map-main` 폴더에서 터미널을 열거나, `cd` 뒤에 그 폴더의 경로를 입력해 이동합니다. 경로에 공백이 있으면 큰따옴표로 감쌉니다.

**Git을 사용하는 방법:**

```bash
git clone https://github.com/RuneDaeg/munhang-map.git
cd munhang-map
```

이후 명령은 모두 **`package.json`이 있는 프로젝트 최상위 폴더**에서 실행합니다. GitHub 토큰을 명령의 URL에 직접 넣지 마세요.

### 1-3. 설치하고 실행

```bash
pnpm install --frozen-lockfile
pnpm local
```

`pnpm local`은 화면을 빌드하고 로컬 서버를 시작한 다음 기본 브라우저를 엽니다. 터미널에 다음과 같은 주소가 나타나면 준비된 것입니다.

```text
문항맵 로컬 주소: http://127.0.0.1:49152/
```

`49152`는 예시이며 실행마다 달라질 수 있습니다. 브라우저가 열리지 않으면 **자신의 터미널에 실제로 표시된 주소**를 복사해 접속하세요. `127.0.0.1:3000`처럼 특정 포트를 고정해서 입력하지 않습니다.

- 실행 중에는 터미널 창을 열어 둡니다.
- API 키가 없어도 PDF 텍스트 추출·문항 전체 캡처·성취기준 후보 확인이 가능합니다.
- 처음 화면의 예시 문항은 업로드한 PDF의 분석 결과가 아닙니다. 자신의 PDF를 선택해 시작하세요.
- 내 문제함과 여러 공급자 연결을 사용하려면 `pnpm dev`가 아니라 **`pnpm local`**로 실행합니다.

## 2. API 연결하기

### API가 필요한 기능

API는 **문항 이미지를 보고 발문·선택지·수식을 다시 읽는 AI 판독**에 사용합니다. 좌표 기반 문항 분리·원문 캡처, 성취기준 후보 검색, 수동 수정, 저장·내보내기는 외부 AI API 없이도 수행합니다.

API가 연결되어 있으면 PDF 분석에 AI 판독이 포함됩니다. 이미 연결된 상태의 분석을 오프라인 작업이라고 생각하면 안 됩니다. 외부 전송을 원하지 않는 자료라면 연결과 데이터 흐름을 먼저 확인하세요.

### 연결 순서

1. 앱 왼쪽의 **API 연결 설정** 또는 **API 연결 변경·사용량 보기**를 누릅니다.
2. **API 공급자**를 선택합니다.
3. 사용할 **모델 ID**를 입력합니다. 문항 이미지를 읽을 수 있는 비전 모델이어야 합니다. 기본값은 참고값이며 계정에서 실제 사용 가능한 모델로 바꿀 수 있습니다.
4. 해당 공급자의 **API 키**를 입력합니다. 키를 README, 소스 코드, 채팅, 오류 제보에 붙여 넣지 마세요.
5. 필요하면 예산과 토큰 단가를 입력하고 **연결 저장**을 누릅니다.
6. **문항맵으로 돌아가기**를 누른 뒤 PDF를 선택합니다.

| 공급자 선택 | 입력할 값 | 주의할 점 |
| --- | --- | --- |
| OpenAI | API 키, 모델 ID | 계정에서 이미지 입력이 가능한 모델 사용 |
| Anthropic Claude | API 키, 모델 ID | 해당 공급자의 키와 모델 ID 사용 |
| Google Gemini | API 키, 모델 ID | 해당 공급자의 키와 모델 ID 사용 |
| OpenAI 호환/로컬 | 기본 주소, 모델 ID, 필요 시 API 키 | Chat Completions 형식, 이미지 입력, JSON 응답을 처리하는 서버 필요 |

**임의의 모든 API가 키만 넣으면 연결되는 것은 아닙니다.** 직접 지원 공급자 또는 호환 API 형식이 필요합니다. 텍스트 전용 모델로는 이미지 판독이 불가능합니다. 연결 저장 시 유료 테스트 요청을 보내지는 않으므로 **‘연결됨’ 표시는 실제 모델 호출 성공을 보증하지 않습니다.**

### 로컬 모델 또는 호환 서비스

별도의 로컬 모델 서버가 준비되어 있다면 **OpenAI 호환/로컬**을 선택하고 서버의 기본 주소와 모델 ID를 입력합니다. 서버를 해당 포트로 설정했다면 `http://127.0.0.1:11434/v1` 같은 주소를 사용할 수 있습니다. 이 주소는 형식 예시이며 문항맵이 모델 서버를 설치하거나 시작해 주지는 않습니다.

- 기본 주소 끝에 `/chat/completions`를 붙이지 않습니다. 앱이 추가합니다.
- 같은 컴퓨터의 루프백 서버는 API 키 없이 연결할 수 있습니다.
- 원격 서비스는 **HTTPS와 API 키**가 필요합니다. 주소에 인증 정보·쿼리·토큰을 넣지 마세요.
- 모델의 이미지 입력 지원 여부와 컴퓨터 성능에 따라 정확도·속도가 달라집니다.

### 키 재입력과 비용 표시

같은 OS 사용자·같은 데이터 위치로 재실행하면 저장한 연결을 재사용합니다. 같은 공급자의 모델·단가만 바꿀 때는 키 입력칸을 비워 두면 기존 키를 유지합니다. 공급자 변경 시에는 새 공급자의 키가 필요하며, 현재는 여러 키 목록이 아니라 **현재 연결 하나**를 관리합니다.

연결 화면에는 공급자·모델·키 끝 4자리·요청 횟수·입력/출력 토큰·추정 사용액을 표시합니다.

- 사용액은 이 앱에서 받은 토큰 사용량과 입력한 단가로 계산합니다.
- 잔액은 입력한 예산에서 앱 추정 사용액을 뺀 값입니다. **공급자의 실제 크레딧 잔액이나 남은 토큰 한도를 조회하지 않습니다.**
- 다른 앱의 사용액, 사용량이 반환되지 않은 요청 등은 포함되지 않을 수 있습니다.
- ‘월 사용 예산’은 계산용 값입니다. 달이 바뀌어도 자동 초기화되지 않으며, 예산 소진 시 요청을 자동 차단하지도 않습니다.
- **사용량 추정치 초기화**는 앱 누적 표시만 초기화합니다. 공급자의 청구액·한도는 바뀌지 않습니다.
- 기본 단가는 참고값입니다. 사용하는 공급자·모델의 가격표와 맞춰 주세요.

## 3. PDF 분석과 문항 검토

### PDF 선택과 진행 화면

1. PDF 선택 영역에서 시험지 파일 하나를 선택합니다.
2. **PDF 읽기 → 문항 분리·캡처 → 발문·수식 판독 → 성취기준 분류** 단계와 처리 건수를 확인합니다.
3. 설정된 단계가 모두 끝나면 문항 목록과 검토 패널이 나타납니다. 중간 텍스트만 추출된 상태를 완료 결과로 먼저 보여 주지 않습니다.

API가 없으면 AI 판독 생략, 일부 요청이 실패하면 원문 보존과 확인 필요 안내를 표시합니다. 오래 걸려도 바로 새로고침하지 말고 진행 건수와 오류를 확인하세요. 여러 PDF 동시 업로드는 아직 지원하지 않으며 **하나씩 분석해 문제함에 모으는 방식**입니다.

### 문항 전체 캡처 확인

목록에서 문항을 선택해 오른쪽 원문 캡처에 아래 내용이 모두 포함되었는지 확인합니다.

1. 문항 번호와 그림 위 간접 발문
2. 그림·그래프·표·자료와 필요한 설명
3. 그림 아래 직접 발문, 보기, 선택지

텍스트형 PDF의 좌표와 단 구성을 이용해 같은 단의 다음 문항 직전까지 캡처합니다. 공통 지문, 다음 단·페이지로 이어지는 내용은 여러 조각으로 보존합니다. AI의 그림 좌표로 전체 캡처를 덮어쓰지 않습니다.

번호를 찾지 못하거나 범위가 불확실하면 페이지 전체 등을 보존하고 확인 안내를 띄울 수 있습니다. **정확히 잘렸다는 보장이 아니므로 원문과 비교해야 합니다.** ‘원문 페이지 펼쳐서 인식 결과 확인’도 사용할 수 있습니다.

넓은 화면에서는 오른쪽 문항 정보가 페이지 스크롤을 따라옵니다. 긴 내용은 패널 안에서 스크롤하며, 문항 변경 시 내부 스크롤이 처음으로 돌아갑니다. 좁은 화면은 세로 배치입니다.

### 캡처나 문항 경계 수정

1. 해당 문항의 **캡처 범위 수정**을 누릅니다.
2. 사각형을 이동하거나 모서리로 크기를 조절합니다. 새 범위를 드래그하거나 네 경계의 비율을 직접 입력할 수도 있습니다.
3. 다음 페이지로 이어지면 페이지를 선택하고 캡처 조각을 추가합니다.
4. **이 범위로 확정**을 누르고 발문부터 선택지까지 확인합니다.
5. 캡처 수정은 텍스트를 자동으로 다시 읽지 않습니다. 필요하면 **문항 전체에서 발문·수식 다시 판독**을 누릅니다. 이 단계는 API를 호출하고 비용이 발생할 수 있습니다.

여러 문항의 텍스트가 붙었다면 입력칸의 새 문항 시작 위치에 커서를 놓고 **커서에서 문항 나누기**를 누릅니다. 한 문항이 둘로 나뉘었다면 **이전 문항과 합치기**를 사용합니다. 텍스트를 나눈 뒤 각 문항의 캡처 범위도 따로 확인하세요. 텍스트 위치만으로 원문 캡처를 임의 변경하지 않습니다.

## 4. 수식과 텍스트 수정

오른쪽 입력칸에서 발문·선택지·숫자를 직접 수정합니다. **일반 문장은 평문**, 실제 수식만 `$...$` 또는 `$$...$$` 안에 씁니다.

```text
다음은 속력에 대한 설명이다. 길이는 20 km이다.
평균 속력은 $v = \frac{s}{t}$로 계산한다.
\bullet 측정값을 비교한다.
\bullet $x^{2} + y^{2} = r^{2}$를 이용한다.
```

- 입력칸은 편집용 원문이므로 LaTeX 코드가 보이는 것이 정상입니다. 아래 **수식 미리보기**와 문항 목록에서 표시 결과를 확인합니다.
- **분수·제곱·루트·단위** 버튼으로 예시 수식을 넣고 수정할 수 있습니다.
- 수식 밖의 `\bullet`, `\circ`, `\times`, `\rightarrow` 등 알려진 기호는 실제 문자로 표시합니다. 완성된 `\frac{…}{…}`, `\sqrt{…}` 등 일부 명령은 구분자 없이도 인식하지만 직접 입력할 때는 `$...$`를 권장합니다.
- 일반 문장 전체를 `\text{…}`로 감싸지 마세요. 과거 결과의 불필요한 `\text`나 탭으로 깨진 `ext{…}`는 **텍스트 표기 정리**로 정리할 수 있습니다. API를 사용하지 않습니다.
- 실제 수식 안의 설명·단위용 `\text`는 보존하며, 미완성·알 수 없는 명령을 무조건 지우지 않습니다. 검토 파일 열기·문제함 읽기·문서 내보내기에도 같은 정리가 적용됩니다.
- 자료표는 일반 행 텍스트로 판독될 수 있습니다. 정확한 배치는 원문 캡처에서 확인합니다.

**중요한 제한:** 웹은 KaTeX로 수식을 표시하지만 DOCX/HWPX에는 정리된 텍스트·LaTeX 원문·문항 전체 캡처를 넣습니다. Word/한글에서 편집 가능한 네이티브 수식이나 원본과 동일한 편집형 표로 변환하는 기능은 아직 없습니다.

## 5. 성취기준 확인과 문서 내보내기

### 교과와 성취기준 선택

시험지 머리말의 과목과 문항 텍스트로 관련 후보를 추천합니다. ‘통합과학’은 통합과학1·2 후보로 좁힙니다. 과거 교육과정 과목명은 관련 2022 개정 교과 후보로 연결할 뿐 교육과정이 같다고 간주하지 않습니다.

1. **이 문항의 교과 후보**를 확인합니다.
2. 원하는 교과가 없으면 **다른 교과 직접 선택**을 누릅니다.
3. **성취기준 후보**에서 코드를 고르고 아래의 실제 기준 문구를 읽습니다.
4. 문항 텍스트 수정 후 **수정한 문장으로 후보 다시 찾기**를 사용할 수 있습니다. 직접 선택한 교과는 재분류·재판독 후에도 우선 반영합니다.

퍼센트는 앱의 관련성 점수를 가공한 표시이며 정답 확률이나 적합성을 보증하는 수치가 아닙니다. 기준 문구는 원본 CSV에서 가져오며 AI가 새 기준을 만들어 넣지 않습니다.

### DOCX/HWPX 다운로드

1. 상단 **문서 내보내기**를 누릅니다.
2. **파일 구성**을 선택합니다.
   - **성취기준마다 파일 분리 · ZIP으로 받기**: 선택된 교과·기준별 문서와 원본 PDF·문항 번호 CSV 목록을 받습니다. 미분류 문항도 별도 보존합니다.
   - **모든 문항을 문서 하나로 받기**: 현재 묶음 전체를 한 문서로 받습니다.
3. **Word · DOCX** 또는 **한글 · HWPX**를 선택합니다.
4. 생성 후 브라우저 다운로드 폴더에서 확인합니다. ZIP은 압축을 풀어 엽니다.

문서에는 수정된 텍스트·성취기준·문항 전체 캡처가 들어갑니다. 배부 전 사용하는 Word/한글에서 페이지 나눔·이미지·글꼴을 확인하세요. HWPX는 구형 바이너리 `.hwp`와 다른 형식입니다.

## 6. 검토 저장과 내 문제함

현재 화면은 자동으로 영구 저장되지 않습니다. 새 PDF 선택·새로고침·종료 전에 목적에 맞게 저장하세요.

| 기능 | 목적 | 저장 내용과 다시 쓰는 방법 |
| --- | --- | --- |
| 검토 저장 | 나중에 범위·텍스트 편집 계속하기 | 원문 페이지, 문항, 교과·기준, 캡처 좌표를 JSON으로 다운로드. **검토 파일 열기**로 재개 |
| 문제함에 저장 | 여러 PDF 문항 모아 재사용하기 | 현재 PDF의 모든 문항 텍스트·기준·캡처를 로컬 문제함에 저장. **내 문제함**에서 검색·선택·내보내기 |

둘 다 API 키를 포함하지 않습니다. 문제함은 원문 전체 페이지가 있는 검토 파일을 대신하지 않습니다. 나중에 캡처 범위를 다시 편집할 작업은 **검토 저장도 함께** 하세요.

### 여러 시험지에서 문항 모으기

1. 첫 PDF를 분석·수정한 뒤 **문제함에 저장**을 누릅니다.
2. 두 번째 PDF도 같은 방법으로 저장합니다.
3. **내 문제함**에서 원본 PDF·교과·성취기준·텍스트로 검색하거나 필터링합니다.
4. 필요한 문항을 여러 PDF에 걸쳐 선택합니다.
5. **선택 문항 내보내기**로 성취기준별 ZIP 또는 한 문서를 받습니다. 원본 PDF 이름과 원래 문항 번호를 유지합니다.

읽기·내보내기는 AI를 다시 호출하지 않습니다. 같은 이름·동일한 원문 페이지의 PDF를 재저장하면 **그 PDF의 스냅샷 전체**를 최신 수정본으로 바꿉니다. 다른 PDF는 건드리지 않지만 같은 PDF의 이전 수정 이력을 버전별로 쌓지는 않습니다.

현재 제한은 한 PDF 저장 **200문항/80MB**, 선택 문항 불러오기 **200문항/120MB**, 문서 ZIP **150MB**입니다. 이미지가 크면 더 적은 문항에서도 제한에 도달할 수 있으므로 나누어 내보내세요.

### 저장 위치와 백업

문제함은 브라우저 저장소가 아닌 OS 사용자 데이터 폴더에 있어, 로컬 주소나 앱 폴더·버전이 바뀌어도 유지됩니다.

| OS | 문제함 폴더 |
| --- | --- |
| macOS | `~/Library/Application Support/문항맵-로컬/question-bank` |
| Windows | `%LOCALAPPDATA%\문항맵-로컬\question-bank` |
| Linux | 기본 `~/.config/munhang-map-local/question-bank` (`XDG_CONFIG_HOME` 설정 시 해당 경로 사용) |

Mac은 Finder의 **이동 → 폴더로 이동**, Windows는 탐색기 주소창에 경로를 입력합니다. 환경 변수 `MUNHANG_DATA_DIR`를 지정했다면 그 아래의 `question-bank`를 사용합니다.

백업은 앱 종료 후 `question-bank` 폴더를 안전한 위치로 복사합니다. 복원 전에도 앱을 종료하고, 현재 문제함이 있다면 먼저 별도 백업하세요. 문제함 간 자동 병합은 지원하지 않습니다. 다른 컴퓨터로 옮기면 API 키는 그 컴퓨터에서 다시 설정하는 것을 권장합니다.

## 7. 재실행과 업데이트

처음 설치 후 다음부터 프로젝트 폴더에서 실행합니다.

```bash
pnpm local
```

종료 전 검토 결과·문제함을 저장하고 터미널에서 **Ctrl+C**를 누릅니다. 브라우저 탭만 닫아서는 서버가 종료되지 않습니다.

Git으로 받았고 소스를 직접 수정하지 않았다면 작업 저장·서버 종료 후 업데이트합니다.

```bash
git pull --ff-only
pnpm install --frozen-lockfile
pnpm local
```

로컬 수정 때문에 중단되면 강제 초기화하지 말고 수정 파일을 먼저 백업하거나 Git 변경 내용을 정리하세요. ZIP으로 받았다면 새 ZIP을 **다른 폴더에** 풀고 설치·실행합니다. 사용자 데이터 폴더를 삭제하지 않는 한 기존 문제함을 재사용합니다. 검토 파일은 앱 폴더 밖에도 보관하세요.

## 8. 로컬 실행 폴더 만들기

이미 만들어진 실행 폴더는 저장소의 **Releases** 페이지에서 `munhang-map-local-*.zip`으로 내려받을 수 있습니다. Node.js만 설치되어 있으면 pnpm·소스 없이 바로 쓸 수 있으므로, 다른 분께 전달할 때는 이 링크를 안내하세요.

직접 만들려면 의존성 설치 후 다음 명령을 실행합니다.

```bash
pnpm local:package
```

결과는 `release/문항맵-로컬`입니다. **폴더 전체를** 복사하거나 ZIP으로 묶어 사용하세요. 실행 파일만 옮기면 안 됩니다.

- Mac: 폴더 안의 `문항맵.command` 실행
- Mac에서 “확인할 수 없는 개발자” 안내로 막히면 `문항맵.command`를 **우클릭 → 열기 → 열기**로 처음 한 번만 실행합니다. 다음부터는 더블클릭으로 열립니다.
- Windows: 폴더 안의 `문항맵.bat` 실행
- 받는 컴퓨터에도 Node.js 22.13 이상은 필요하지만, 빌드된 실행 폴더 사용에 pnpm·`node_modules` 설치는 필요하지 않습니다.
- 내부 `renderer/index.html`을 직접 열지 않습니다.

`pnpm local:release`를 쓰면 폴더 생성과 ZIP 압축까지 한 번에 끝납니다. 배포용 ZIP은 저장소에 커밋하지 않습니다. `package.json`의 `version`을 올리고 `v0.5.2` 같은 태그를 푸시하면 `.github/workflows/local-release.yml`이 ZIP을 만들어 검증한 뒤 릴리스에 첨부합니다.

```bash
git tag v0.5.2
git push origin v0.5.2
```

`local:package`는 기존 `release/문항맵-로컬` **생성 폴더를 다시 만듭니다**. 그 안에 개인 PDF·검토 파일을 보관하지 마세요. GitHub의 **Download ZIP은 소스 압축 파일**이지 빌드된 실행 폴더가 아닙니다. `release/`는 소스 저장소에 포함하지 않습니다.

## 9. 개인정보와 API 키 보안

- 서버는 `127.0.0.1`에만 열립니다. PDF·문제함이 GitHub로 자동 업로드되지는 않습니다.
- 기본 읽기·캡처는 브라우저에서 수행하지만 **AI 판독 시 대상 문항 이미지와 텍스트를 선택한 API 공급자에게 보냅니다.** 신뢰하는 공급자와 서버만 연결하세요.
- Mac 키는 **macOS 키체인**에 저장합니다. 브라우저 저장소에 보관하거나 저장된 전체 키를 화면에 재표시하지 않습니다.
- Windows/Linux의 로컬 서버는 키를 암호화 파일에 보관하지만 복호화용 파일도 같은 사용자 데이터 영역에 있습니다. OS 보안 금고와 같은 보호 수준이 아니며, 그 폴더에 접근 가능한 악성 프로그램·사용자로부터 완전히 보호하지 못합니다.
- 문제함과 검토 JSON은 **암호화되지 않은 시험지 텍스트·이미지**를 포함합니다. 개인정보와 재배포 권한을 확인하세요.
- 키체인, `api-key.enc`, `local-master-key.bin`, 연결 설정, `.env`를 저장소·공유 ZIP·오류 제보에 넣지 마세요. 화면·로그 공유 전에도 키와 개인 자료를 가리세요.
- 공급자 측 사용 한도·알림도 설정하세요. 앱 예산 표시만으로 과금을 막을 수 없습니다.

소스 공개와 개인 데이터 공개는 별개지만, `.gitignore`만으로 실수나 키 유출을 완전히 막지는 못합니다. 저장소 안으로 파일을 옮겼다면 커밋 전 목록을 확인하세요.

## 10. 자주 겪는 오류

### `node` 또는 `pnpm`을 찾을 수 없음

Node.js 설치 후 터미널을 닫고 다시 엽니다. `node --version`, `pnpm --version`을 확인합니다. pnpm만 없다면 1장의 설치 명령을 사용하세요. Windows PowerShell의 `pnpm.ps1` 실행 정책 오류는 시스템 보안 정책을 낮추기보다 **명령 프롬프트**나 `pnpm.cmd`를 사용해 해결하세요.

### `package.json`을 찾을 수 없음 / 의존성 설치 실패

압축을 완전히 풀었는지, `package.json`·`pnpm-lock.yaml`이 있는 최상위 폴더인지 확인합니다. pnpm은 10을 사용합니다. 오류 메시지와 인터넷·프록시 설정을 확인하고, 잠금 파일을 임의 삭제해 버전을 섞지 마세요.

### Mac에서 “확인할 수 없는 개발자”라며 열리지 않음

인터넷·메신저로 받은 파일에는 격리(quarantine) 속성이 붙어 Gatekeeper가 첫 실행을 막습니다. 파일이 손상된 것이 아닙니다. `문항맵.command`를 **우클릭 → 열기 → 열기**로 한 번만 실행하면 이후에는 더블클릭으로 열립니다. 그래도 막히면 **시스템 설정 → 개인정보 보호 및 보안**에서 차단 기록 옆의 **확인 없이 열기**를 누릅니다. 보안 설정 전체를 낮추지는 마세요. 폴더를 옮기는 과정에서 실행 권한이 사라졌다면 폴더 안에서 `chmod +x 문항맵.command`로 되돌립니다.

### 접속 실패 또는 ChatGPT 로그인 화면

이전 호스팅 사이트·북마크가 아니라 현재 터미널의 **`http://127.0.0.1:숫자/` 주소**로 들어갑니다. 서버를 닫았다면 다시 실행합니다. 이 로컬 앱은 ChatGPT 로그인 없이 시작합니다.

### PDF `Setting up fake worker failed` / JavaScript MIME 오류

HTML 직접 열기나 임의의 정적 서버 대신 **`pnpm local` 또는 빌드된 런처**로 실행합니다. 현재 서버는 `.mjs` PDF worker를 `text/javascript`로 제공합니다. 최신 소스로 실행 폴더를 다시 만들고 이전 서버를 종료한 뒤 새 주소로 접속하세요.

### 스캔 PDF라서 텍스트를 읽을 수 없음

현재 문항 분리에는 PDF 텍스트 레이어가 필요합니다. 사진만 있는 PDF는 자동 OCR 일괄 처리로 이어지지 않습니다. 먼저 OCR 도구로 검색 가능한 텍스트 레이어를 만든 PDF를 사용하세요. API 키 추가만으로 이 제한이 사라지지 않습니다.

### API 저장 후에도 실패 / 오래 진행 중

공급자·키 일치 여부, 모델 ID·이미지 지원, 권한·사용 한도, 호환 서버 실행 여부를 확인합니다. 401/403은 인증·권한, 429는 한도·요청 제한일 수 있으므로 공급자의 원래 오류 메시지도 확인하세요. ‘연결됨’만으로 호출 성공을 보증하지 않습니다. 연결을 고친 뒤 실패한 문항만 재판독할 수 있지만 재시도에는 추가 비용이 발생할 수 있습니다.

### 그림 위 발문이나 아래 선택지가 빠짐

**캡처 범위 수정**으로 문항 전체를 포함시키고 확정합니다. 캡처는 맞고 텍스트만 빠졌다면 직접 보완하거나 **문항 전체에서 발문·수식 다시 판독**을 사용합니다. 캡처 변경과 텍스트 재판독은 별도 작업입니다.

### 키를 계속 요구하거나 문제함이 비어 있음

같은 OS 사용자인지, `MUNHANG_DATA_DIR`·데이터 폴더가 바뀌었는지, macOS 키체인 접근이 가능한지 확인합니다. 호스팅 사이트·Electron·`pnpm dev`가 아니라 현재 로컬 서버인지도 확인합니다. 키 전체나 데이터 폴더를 오류 제보에 첨부하지 마세요.

### 문서에 LaTeX 코드가 남음 / 큰 문서 내보내기 실패

네이티브 편집 수식은 아직 지원하지 않습니다. 정확한 모양은 첨부한 원문 캡처로 확인합니다. 파일이 너무 크면 내 문제함에서 문항을 적게 선택해 여러 묶음으로 내보내세요.

## 11. 개발 및 검증

로컬 실행은 `desktop/vite.renderer.config.ts`로 React 화면을 빌드하고 `local/server.cjs`로 제공합니다. 웹 개발·Sites 설정은 남아 있지만 로컬 사용에 호스팅 배포나 `.env.local` 설정은 필요하지 않습니다.

주요 코드 위치:

- `app/page.tsx`, `components/`: 업로드·진행·검토·문제함·내보내기 UI
- `lib/pdf-layout.ts`, `lib/pdf-analysis.ts`, `lib/question-capture.ts`: PDF 문항 분리·과목 감지·캡처
- `lib/math-normalization.ts`, `components/math-text.tsx`: 텍스트 정리·KaTeX
- `lib/vision-recognition.ts`, `desktop/provider-client.cjs`: 판독·공급자별 요청
- `lib/document-export.ts`: DOCX/HWPX·성취기준 ZIP
- `local/server.cjs`, `local/question-bank.cjs`: 로컬 API·연결·문제함
- `public/data/`, `public/hwpx-template/`: 출처가 명시된 성취기준·템플릿
- `tests/`: 합성 입력·모의 API 응답 기반 회귀 테스트

설치 후 다음으로 검사합니다.

```bash
pnpm test:pdf
pnpm test:math
pnpm test:providers
pnpm test:workflow
pnpm exec tsc --noEmit
pnpm desktop:renderer
pnpm test:local
```

`test:local`은 빌드 파일과 로컬 포트가 필요하므로 `desktop:renderer` 다음에 실행합니다. 임시 데이터 폴더로 저장·재시작·접근 제한을 검사하며 실제 문제함은 사용하지 않습니다. 위 테스트는 유료 AI를 호출하지 않습니다. 모의 테스트가 모든 실제 공급자·모델의 호환성이나 임의 시험지의 정확도를 보증하지는 않습니다.

변경 후에는 실제 환경에서 PDF 선택 → 캡처 수정 → 기준 선택 → 검토 저장·재열기 → 두 PDF 문제함 저장 → 선택 문항 내보내기도 확인하세요. 오류 제보에는 문항 번호·쪽·기대 범위를 적고 공유 권한이 있는 비민감 예제만 사용합니다.

### 선택 사항: Electron 설치 파일

로컬 브라우저 사용에는 필요하지 않습니다. 기존 빌드 코드는 다음과 같이 유지되어 있습니다.

```bash
pnpm desktop:mac
pnpm desktop:win
```

Mac용 ARM64 DMG, Windows용 x64 EXE 설정이며 `release/`에 생성됩니다. OS별 빌드 환경·코드 서명·공증은 별도 준비가 필요합니다. `.github/workflows/desktop-build.yml`은 수동 실행 또는 `desktop-v*` 태그 푸시 때 빌드를 시도하며, 일반 `main` 푸시만으로 자동 배포하지 않습니다. 로컬 실행본은 이와 별개로 `v*` 태그를 쓰는 `local-release.yml`이 담당합니다(8장 참고). **내 문제함은 현재 로컬 서버 실행본에서 지원하며 Electron과 기능이 완전히 같지는 않습니다.**

서명·공증하지 않은 DMG·EXE는 받는 컴퓨터에서 macOS Gatekeeper나 Windows SmartScreen이 먼저 차단합니다. Mac은 앱을 **우클릭 → 열기 → 열기**, Windows는 SmartScreen 안내에서 **추가 정보 → 실행**을 거쳐야 설치됩니다. 배포 대상이 넓다면 서명·공증을 준비하는 편이 낫습니다.
