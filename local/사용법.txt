문항맵 로컬 실행 0.7.14

0.7.14 · 버전 확인과 문제함 문항 수정
- 상단 ‘버전 확인’을 누르면 현재 실행 버전과 GitHub 정식 로컬 릴리스를 비교합니다. 최신 실행 ZIP이 있으면 다운로드 링크를 제공합니다. 시험지·문항·API 키는 전송하지 않으며 자동 설치하지 않습니다.
- 앱을 열기만 해서는 버전 확인을 요청하지 않습니다. 버튼을 누른 결과는 1분간 재사용하며, 인터넷 오류·요청 제한·ZIP 준비 중은 따로 안내합니다. 현재 로컬 버전이 공개판보다 새로우면 이전 버전으로 내리지 않습니다.
- ‘내 문제함 → 문항 수정’에서 텍스트·LaTeX·상자·표·굵게·밑줄을 고칩니다. ‘수식 검사’와 미리보기를 확인하고 ‘수정 저장’을 누른 뒤 내보내세요. 캡처·성취기준·다른 문항은 유지합니다. API는 호출하지 않습니다.
- 새 문제함 저장 및 수정 저장 전에 화면·DOCX·HWPX 수식 변환을 검사합니다. 실패하면 문항 번호와 원인을 알리고 저장하지 않습니다. 수식의 의미나 정답 정확도를 보증하는 검사는 아닙니다.
- 오류가 있는 기존 문항도 편집할 수 있습니다. 저장 실패·다른 창과의 수정 충돌에서는 초안을 유지합니다. 편집을 닫거나 다른 문항으로 이동할 때 미저장 변경이 있으면 확인하며, 수정 내용을 저장/취소하기 전에는 내보내기를 막습니다.
- ‘다른 실행에서 저장 중’ 안내가 계속 남으면 초안을 복사하고 모든 문항맵 실행을 종료한 후, 안내에 나온 .jsonl.lock 파일만 제거하고 다시 실행하세요. 실제 문제함 .jsonl 파일은 삭제하지 마세요.
- 새 ZIP은 이전 서버 종료 후 별도 폴더에 전부 풀어 실행합니다. 같은 사용자 데이터 폴더의 문제함·연결 설정은 유지됩니다. 공식 릴리스: https://github.com/RuneDaeg/munhang-map/releases

외부 반출 금지 문서를 넣지 마세요
- 미공개 시험지·출제 중 문항·개인정보·기관 기밀 등 외부 전송이 금지된 자료는 사용하지 마세요.
- 최초 PDF 분석은 로컬 처리입니다. 개별/전체 API 판독을 별도로 실행·확인하면 문항 캡처·추출문(공통 지문 포함)이 선택한 AI 공급자 또는 설정한 서버로 전송됩니다.
- API 키를 로컬에 보관해도 문서의 외부 전송을 막아주지는 않습니다. 첫 화면·API 연결 화면·판독 확인창의 경고는 반출 금지 여부를 자동 판별하거나 전송을 자동 차단하는 기능은 아닙니다.

1. Node.js 22.13 이상 LTS 버전을 설치합니다: https://nodejs.org
2. Mac은 “문항맵.command”, Windows는 “문항맵.bat”를 실행합니다.
   Mac에서 “확인할 수 없는 개발자” 안내로 열리지 않으면 “문항맵.command”를 우클릭 → 열기 → 열기를 처음 한 번만 해 주세요.
3. PDF를 넣거나 ‘검토 파일 열기’를 누릅니다. 저장된 API 키가 있어도 PDF 업로드에서는 AI를 호출하지 않습니다. ‘이 문항만 API로 판독’ 또는 상단 ‘전체 문항 API 판독’을 누르고 전송·비용 안내를 확인하면 별도로 AI 판독을 실행합니다.
4. 실행 중인 터미널 창을 닫으면 로컬 문항맵도 종료됩니다.

문항 추출
- 최초 PDF 업로드는 로컬 처리만 합니다. 텍스트 추출·문항 분리·전체 캡처·검증된 글꼴/좌표에 따른 수식 복원·성취기준 후보 추천에는 AI API 전송이나 비용이 없습니다.
- 텍스트형 PDF의 머리말에서 시험 과목을 읽어 성취기준 후보에 반영합니다.
- 발문, 그림·표·자료, 질문과 선택지를 포함한 문항 전체 캡처는 API 키 없이 생성됩니다.
- 문항 전체 캡처는 DOCX/HWPX에도 첨부됩니다. 경계 확인 안내가 있는 문항은 원문과 비교해 주세요.
- ‘캡처 범위 수정’에서 상자를 끌거나 모서리를 조절한 뒤 ‘이 범위로 확정’을 누르세요.
- ‘검토 저장’으로 수정한 결과를 파일로 보관하고, 다음에는 ‘검토 파일 열기’로 이어서 수정할 수 있습니다.
- 검토 파일에는 시험지 원문이 포함되며 API 키는 포함되지 않습니다.
- 일반 문장은 평문, 실제 수식만 $…$로 입력합니다. AI 판독도 이 형식으로 요청합니다.
- 수식 바깥의 \bullet, \circ, \times, \rightarrow 같은 기호도 표시합니다. 문항 목록에도 수식이 렌더링됩니다.
- 넓은 화면에서는 오른쪽 문항 정보가 스크롤을 따라옵니다. 내용이 길면 패널 안에서 스크롤하세요. 다른 문항을 선택하면 패널 내부 스크롤이 처음으로 돌아갑니다.
- 이미 깨진 문장은 ‘텍스트 표기 정리’로 불필요한 text 표기와 탭을 정리할 수 있습니다. API를 사용하지 않습니다.
- 검토 파일을 열거나 문서로 내보낼 때에도 같은 정리가 적용됩니다. 화면은 KaTeX로 수식을 표시합니다. 지원되는 수식은 DOCX에서 Word의 네이티브 수식(OMML), HWPX에서 한글의 네이티브 수식으로 변환하며 원문 캡처도 첨부합니다.
- 스캔형 PDF는 먼저 OCR 처리가 필요합니다.

API 키 발급 안내 (공식 안내 확인일: 2026-09-12)
- ‘API 연결 설정’ 화면에서 OpenAI·Anthropic Claude·Google Gemini 안내를 펼쳐보세요. 공식 페이지는 새 탭으로 열리며 안내 확인이나 연결 저장만으로 API 판독이 실행되지는 않습니다.
- OpenAI: https://platform.openai.com/api-keys 로그인 → 사용할 프로젝트에서 키 생성 → 복사 → 문항맵에서 OpenAI 선택·키 입력·연결 저장.
  공식 안내: https://developers.openai.com/api/docs/quickstart
- Claude: https://platform.claude.com/settings/keys 로그인 → Create key → 이름·만료 기간·본인 계정·사용할 워크스페이스 지정 → 복사 → Claude 선택·저장. 문항맵에서는 하나의 워크스페이스에 범위를 지정한 키를 사용하세요.
  공식 안내: https://platform.claude.com/docs/en/manage-claude/authentication
- Gemini: https://aistudio.google.com/apikey 로그인 → 사용 가능한 프로젝트 선택·필요 시 가져오기 → API 키 생성·복사 → Gemini 선택·저장. 프로젝트가 안 보이거나 생성 권한이 없으면 관리자에게 문의하세요.
  공식 안내: https://ai.google.dev/gemini-api/docs/api-key
- 계정에서 이미지 입력이 가능한 모델을 사용하세요. API 요금·무료 할당·결제 필요 여부는 공급자 콘솔에서 확인합니다. 콘솔 메뉴와 정책은 변경될 수 있습니다.
- 키를 채팅·문서·공개 저장소·스크린샷에 넣지 마세요. 노출이 의심되면 공급자 콘솔에서 폐기하고 새 키로 변경하세요. 문항맵에 표시되는 예산·잔액은 앱 추정치이며 공급자의 실제 잔액·결제 한도가 아닙니다.

필요한 문항만 API로 판독
- 로컬 추출 결과를 먼저 원문과 비교하고, AI 판독이 필요한 문항 하나를 선택합니다.
- ‘이 문항만 API로 판독’을 누릅니다. 연결이 없다면 먼저 API 공급자·이미지 입력 가능한 모델·키를 설정하세요. 연결 저장만으로 PDF를 자동 판독하지는 않습니다.
- 확인창의 문항 번호·공급자와 해당 문항 이미지·텍스트 전송 및 비용 발생 가능성을 확인한 뒤 진행합니다. 해당 문항에 연결된 공통 지문도 포함될 수 있습니다. 취소하면 API를 호출하지 않습니다. 다른 문항이나 PDF 전체를 함께 판독하지 않습니다.
- 직접 편집한 문항에는 덮어쓰기 경고도 표시합니다. 필요한 수정본을 먼저 ‘검토 저장’으로 백업하세요. 응답을 기다리는 동안 추가로 수정한 내용은 덮어쓰지 않습니다.
- 실패하거나 불완전한 응답이면 기존 내용을 보존하고 확인 안내를 표시합니다. 다시 시도할 때도 사용자가 이 버튼을 눌러 확인하며 API 비용이 발생할 수 있습니다.
- PDF 전체의 자동 AI 판독을 켜는 옵션은 없습니다. 저장된 키는 삭제하지 않으며, 같은 OS 사용자·같은 데이터 위치에서는 이 기능을 쓰려고 키를 다시 입력할 필요가 없습니다.
- 성취기준 후보 추천·다시 찾기, 수동 편집, 검토 저장·문제함 읽기, 수식 변환·내보내기는 AI를 호출하지 않습니다. 로컬 추출과 AI 판독 모두 초안이므로 원문과 대조해 주세요.

영어 발문·선택지 번호 보존
- AI에게 한국어 발문, 영어 지문 전체, 선택지 문장과 원문 번호를 각각 보존하도록 요청합니다.
- 원문 추출문에 선택지 번호가 있거나 AI가 별도 선택지 배열을 반환하면 번호와 문장의 대응을 확인해 ①~⑤와 줄바꿈을 복원합니다. 어법 문제의 지문 내부 번호는 원래 위치에 남깁니다.
- 선택지 누락 또는 번호 감소를 감지하면 기존 내용을 보존하고 경고합니다. 근거 없는 평문을 임의로 5개로 나누지는 않습니다.
- 이미 번호가 없는 결과는 먼저 ‘검토 저장’으로 백업하고, 최신 버전에서 원문 캡처 범위를 확인한 뒤 ‘이 문항만 API로 판독’을 누르고 전송을 확인하세요. 판독은 연결한 API 사용 비용이 발생할 수 있습니다.

숫자·수식 글자가 네모로 보일 때
- 0.7.2는 검증된 HyhwpEQ·HancomEQN 글꼴의 숫자·변수·분수·루트·첨자를 API 없이 복원합니다. 글꼴 이름뿐 아니라 실제 글자 모양도 확인합니다. 표 경계와 다른 기준선을 넘지 않고 흩어진 숫자를 묶습니다.
- 미복원 문자가 하나라도 남으면 해당 문항에 ‘문자 복원 확인 필요’와 개수가 표시됩니다. 성취기준 % 대신 자동 검토 항목과 추천 근거를 표시합니다. ‘자동 경고 없음’도 정확성이나 검토 완료를 보증하지 않습니다.
- 수동 수정본은 먼저 ‘검토 저장’으로 백업하고, 새 버전을 실행한 뒤 원본 PDF를 다시 넣으세요. 새 PDF는 현재 분석 목록을 바꿉니다. 기존 검토 파일이나 문제함에는 글꼴 정보가 없으므로 그것만 열어서는 예전 깨짐이 복원되지 않습니다.
- 미지원 글꼴과 복잡한 수식 배치는 원문을 대조해 수정하거나 이미지 판독 API를 이용하세요. 기본 문자 복원과 AI 재판독은 다릅니다. AI 요청에는 비용이 발생할 수 있습니다.

표·자료 상자·보기
- PDF 내부의 텍스트 좌표와 테두리 선으로 표·상자를 로컬에서 복원합니다. API 호출은 필요하지 않습니다. 짧게 나뉜 선, <보기> 제목으로 끊긴 윗선, 바깥 세로선이 없는 표도 처리합니다.
- 표 일부 열만 가로지르는 부분 가로선도 세부 행의 경계로 읽습니다. 세로로 병합된 부모 제목은 각 자식 행에 반복하고, 자식 행의 수치·단위·열 대응을 유지합니다. 원본의 실제 셀 병합을 그대로 복제하지는 않습니다.
- 선택지 표는 ① 위의 머리글과 각 열을 함께 포함합니다. 여러 줄 제목, 영어 (A)/(B), 표 바깥의 번호도 확인합니다. 넓은 표는 가로 스크롤하세요.
- AI 재판독이 기존 표·상자나 머리글을 누락하면 원래 구조를 보존하고 경고합니다.
- 이미지 입력 가능한 API를 연결한 뒤 ‘이 문항만 API로 판독’을 눌러 확인하면 해당 문항의 표와 자료 상자도 함께 인식하도록 요청합니다. PDF 업로드나 연결 저장만으로 이 요청을 보내지 않습니다.
- 문장 자료와 <보기>는 각각 한 칸짜리 표로, 행·열 자료는 여러 셀의 표로 DOCX/HWPX에 넣습니다.
- 상자 밖 발문·질문·선택지는 표 밖에 유지하며, 문항 전체 캡처도 계속 첨부합니다.
- 명확한 <보기> 제목·ㄱ/ㄴ 항목·①/② 선택지 경계가 있으면 AI 표식이 없어도 로컬 규칙으로 상자를 묶습니다. 공백과 항목 중간 줄바꿈도 처리하며 추가 API 비용은 없습니다. 예전 검토 파일이나 문제함을 열어도 적용됩니다.
- 새 좌표 알고리즘을 적용하려면 수정본을 먼저 검토 저장한 뒤 PDF를 다시 선택하세요. 이 재추출은 로컬 처리입니다. 예전 검토 파일만 열면 PDF의 선 정보를 다시 읽을 수 없습니다. ‘이 문항만 API로 판독’은 전송 확인 후 실행하는 별도의 AI 요청으로 비용이 발생할 수 있습니다.
- 이미 잘린 표가 검토 파일·문제함에 저장되어 있다면 원본 PDF를 다시 선택해 추출해야 합니다. 빠진 세부 행과 값은 예전 저장 파일을 여는 것만으로 복원되지 않습니다.
- 입력칸 아래 ‘자료 상자 삽입’, ‘보기 상자 삽입’, ‘자료표 삽입’으로 직접 만들 수도 있습니다. API 없이 사용할 수 있습니다.
- :::box 또는 :::table로 시작하고 마지막 별도 줄의 :::로 닫습니다. 표 행은 |로 시작·종료하며 모든 행의 열 수를 맞춥니다. 잘못된 구조는 텍스트로 보존합니다.
- ‘문항 미리보기 · 수식·표·보기’는 원문 캡처 아래, 텍스트 편집창 위에 있습니다. 상자·표 개수를 확인하고 텍스트 편집칸에서 수정하세요. 저장·문제함·성취기준별 내보내기에도 구조가 유지됩니다.
- 화면 상단 문항맵 옆의 버전이 v0.7.13인지 확인하세요. 옛 서버를 종료하고 새 폴더의 실행 파일을 여세요.
- 로컬 선 분석은 텍스트형 PDF 대상이며 스캔 이미지의 모든 박스를 찾는 기능은 아닙니다. 작은 표와 상자 안의 여러 표를 함께 보존합니다. 좌우 두 묶음의 선택지는 머리글이 같을 때만 한 표로 합칩니다.
- DOCX는 상자 안의 표를 중첩된 편집형 표로 보존합니다. HWPX는 표 잘림 위험을 줄이기 위해 바깥 설명 상자와 내부 표를 같은 폭의 연속 구간으로 출력하므로 외곽선이 원문과 다를 수 있습니다. 한컴 앱의 실제 표시 결과는 확인이 필요합니다.
- 병합 셀은 일반 격자로 풀어 표현합니다. 셀 안 그림·원본과 동일한 크기는 지원하지 않으므로 원문 캡처와 대조하세요. 비정형 그림 선택지는 번호를 포함한 원본 이미지로 보존하고 확인 안내를 표시합니다.
- 직접 편집한 문항을 API로 재판독하기 전에는 확인을 받습니다. 재판독 응답을 기다리는 동안 수정한 내용은 덮어쓰지 않습니다.

분석 진행과 내보내기
- PDF 읽기·문항 분리/캡처·로컬 수식 복원·성취기준 후보 추천이 끝날 때까지 진행 화면을 유지합니다.
- 저장된 API 연결 유무와 관계없이 PDF 업로드에서는 AI 판독을 실행하지 않습니다. 필요한 문항은 추출 후 사용자가 별도로 선택해 API 판독을 요청합니다.
- ‘내보내기’에서 성취기준마다 DOCX/HWPX 파일을 나눈 ZIP을 받을 수 있습니다. 원본 PDF·문항 번호 목록도 포함됩니다.
- DOCX와 HWPX 모두 변환할 수 없는 명령·구조나 잘못된 수식이 있으면 문항 번호가 포함된 오류를 표시하고 내보내기를 중단합니다. 해당 문항의 수식을 수정한 뒤 다시 내보내세요. 모든 LaTeX 명령·글꼴·수식 내부 부분 서식을 지원하는 것은 아닙니다.
- 이전 버전의 일부 수식은 macOS Microsoft Word에서 확인했습니다. 0.7.13 전체 문항을 Word·한컴·Windows 실기기에서 표시 검증한 것은 아닙니다. LibreOffice에서는 일부 수식 글꼴·분수 간격이 다르고, 작은 수식 상자의 내용은 남지만 테두리가 보이지 않을 수 있습니다. 실제 사용 앱에서 원문과 대조하세요.

굵게·밑줄
- PDF 글꼴·그리기 방식·밑줄 선에서 서식 근거를 찾으면 원문 굵게·밑줄도 자동 보존합니다. [A]/[B] 괄호 범위는 자료 상자로 표현합니다. 자동 서식은 원문과 대조해 주세요.
- 0.7.8은 글자 기준선과 밑줄 사이 거리를 보완하고 표 테두리·분수선을 구분합니다. AI 판독 후에도 원문에서 서식이 확인된 구절이 같은 내용으로 대응하면 굵게·밑줄을 다시 적용합니다. 바뀐 내용이나 여러 번 반복되어 대응이 모호한 구절에는 임의로 적용하지 않습니다.
- 예전 검토 파일·문제함에서 밑줄이 이미 빠졌다면 수정본을 검토 저장한 뒤 원본 PDF를 다시 분석하세요. 저장 파일만 열면 원본의 선 좌표를 다시 읽을 수 없습니다.
- 오른쪽 텍스트 편집창에서 글자를 선택하고 Mac은 Cmd+B/U, Windows는 Ctrl+B/U를 누릅니다. B 굵게/U 밑줄 버튼도 사용할 수 있습니다. 다시 누르면 해제합니다.
- LaTeX를 쓰지 않아도 되며, 검토 저장·문제함·DOCX/HWPX 내보내기에 글자 서식이 유지됩니다.
- 표·박스 경계 표식에는 서식이 적용되지 않습니다. 외부 붙여넣기는 텍스트만 가져옵니다. AI 재판독 전에 수동 수정본을 백업하세요.

내 문제함
- PDF 분석 후 ‘문제함에 저장’을 누르면 현재 PDF의 모든 문항과 캡처를 이 컴퓨터에 저장합니다.
- 같은 이름·원문의 PDF를 다시 저장하면 그 PDF의 기존 저장본을 최신 수정본으로 갱신합니다.
- ‘내 문제함’에서 여러 PDF의 문항을 검색·선택하고 함께 내보낼 수 있습니다. 저장된 문항을 다시 AI 분석하지 않으므로 API 비용은 없습니다.
- 앱을 종료하거나 새 버전으로 실행해도 문제함은 유지됩니다. API 키는 문제함에 포함되지 않습니다.
- 백업은 앱 종료 후 Mac의 Library/Application Support/문항맵-로컬/question-bank, Windows의 %LOCALAPPDATA%/문항맵-로컬/question-bank 폴더를 복사하면 됩니다.
- 문제함 파일은 암호화하지 않으며 시험지 텍스트와 이미지가 포함됩니다. 다른 사람과 공유할 때 주의하세요.
- 한 번에 200문항까지 선택할 수 있습니다. 큰 문항 묶음은 나누어 내보내세요.

0.7.10 전체 문항 API 판독·왼쪽 첨자 보완
- ‘이 문항만 API로 판독’은 유지하고 상단에 ‘전체 문항 API 판독’을 추가했습니다. PDF 업로드는 계속 API 없이 진행됩니다.
- 전체 판독은 현재 목록의 1~200문항을 한 문항씩 순서대로 요청합니다. 이미 판독한 문항도 다시 요청하므로 비용이 추가될 수 있습니다. 대상 수·공급자·공통 지문·비용 안내를 확인하고 실행하세요.
- 완료 수와 현재 문항을 표시합니다. ‘현재 문항 후 중단’을 누르면 진행 중 요청까지만 마치며, 이미 전송된 요청의 비용은 취소되지 않을 수 있습니다. 실패하면 다음 요청을 멈추고, 완료된 결과는 유지합니다. 요청 중 직접 편집한 문항은 덮어쓰지 않습니다.
- 원소 기호가 H +, H →처럼 연산자와 한 덩어리인 PDF에서도 실제 좌표를 근거로 왼쪽 위 질량수·아래 양성자 수를 복원합니다. API 응답이 원문에서 확인된 첨자·원소·반복 개수를 잃으면 원문을 유지하고 경고합니다. 판독 후 기존 발문 전체가 중복되는 경우도 보완했습니다.
- 첨자를 추측하여 채우지는 않습니다. 기존 수정본을 검토 저장한 뒤 원본 PDF를 다시 선택해야 새 좌표 복원이 적용됩니다. 모든 PDF의 수식·표·밑줄이 해결된 것은 아니며 원문 대조가 필요합니다.

0.7.9에서 도입한 로컬 우선 분석
- API 키가 저장되어 있어도 최초 PDF 업로드에서 AI 판독을 자동 실행하지 않습니다. 문항 분리·캡처·수식 복원·성취기준 추천은 로컬에서 계속 사용할 수 있습니다.
- API 판독은 사용자가 전송·비용 안내를 확인한 경우에만 실행합니다. 0.7.10에서는 한 문항 판독과 수동 전체 판독을 모두 지원하며 업로드 직후 자동 판독은 하지 않습니다.
- 기존 API 키·연결 설정은 유지되며, 로컬 추출을 위해 키를 삭제하거나 한 문항 판독 때마다 다시 입력할 필요가 없습니다. 직접 편집한 문항의 덮어쓰기 경고와 요청 중 수정 내용 보호도 유지합니다.

0.7.8부터 포함된 한글 편집 수식·원문 밑줄·음수 지수 개선
- HWPX 본문·자료 상자·표 셀의 지원되는 분수·근호·첨자·화학식과 전하·합·극한·행렬·구간별 함수를 한글에서 편집 가능한 수식 객체로 내보냅니다. 수식 변환과 내보내기는 API를 호출하지 않습니다.
- 올바른 수식이 있는 기존 검토 파일은 다시 열고 HWPX로 내보내면 새 변환이 적용됩니다. 원문 캡처도 유지됩니다.
- PDF에서 부호와 숫자가 같은 작은 글자 기준선에 놓인 음수 지수를 하나로 복원합니다. 10^{−}^{27}처럼 분리되던 배치는 10^{−27}로 묶고, 실제 중첩 지수·위아래 첨자는 유지합니다.
- 이미 잘못 분리된 지수나 빠진 밑줄이 저장되어 있으면 원본 PDF를 다시 선택해 분석해야 합니다. 옛 검토 파일을 여는 것만으로 없는 좌표 정보나 수식 의미를 추측해서 고치지는 않습니다.
- 기존 수정본을 검토 저장한 뒤 옛 서버를 종료하고 새 ZIP을 별도 폴더에 전부 풀어 실행하세요. 이전 릴리스·개인 문제함·API 설정은 유지됩니다.

0.7.7부터 포함된 수식·표·줄바꿈 개선
- DOCX는 지원되는 수식을 Word의 네이티브 편집 수식(OMML)으로 내보냅니다. 0.7.7 당시의 HWPX LaTeX 원문 보존 방식은 0.7.8에서 한글 네이티브 수식 변환으로 바뀌었습니다.
- 화학 문맥에서 확인한 분자식·이온식은 원소 기호를 세운 글꼴로 표시하고 첨자·전하는 보존합니다. 물리·수학 변수는 기본 이탤릭으로 유지하며 모호한 영문·유전자 표기를 임의로 화학식으로 바꾸지 않습니다.
- 일반 본문의 원형 목록 기호나 ㄱ·ㄴ·ㄷ 항목 앞에 문자로 남은 \n을 실제 줄바꿈으로 정리합니다. 정상 LaTeX 명령, 배열·cases 행 구분, 코드·인용 문자열은 보존합니다.
- 분할된 표 셀은 별도 자식 행으로 보존합니다. 기존 결과에서 이미 빠진 표 내용은 원본 PDF 재추출이 필요합니다.

0.7.13 과학탐구 추출 보정
- 전용 글자·분수·첨자·벡터·밑줄·자료 상자·작은 빈칸·독립 표와 문장 순서를 보정합니다.
- 일반 변수의 오른쪽 첨자와 핵종의 왼쪽 첨자를 구분하고, API가 확인 가능한 원문 배치를 훼손하면 기존 내용을 유지하고 안내합니다.
- F₁·p₁처럼 원소 기호와 겹치는 일반 변수도 보호합니다. 핵종 교정은 명확한 핵 문맥과 원문에 있는 위·아래 숫자가 모두 일치하는 경우만 예외로 둡니다.
- 수식 부분의 밑줄·작은 원문자 박스 높이·단위 중점 순서·표 셀의 목록 줄바꿈을 보완했습니다.
- 충격량·전기력·속성 작용·생물 특성·태풍·해파·지형류는 확인 가능한 평가 내용과 후보 전문으로 범위를 좁힙니다. 전체 매핑의 정확도를 보증하는 규칙은 아닙니다.
- 원문에 없는 숫자나 원소를 추측해서 채우지 않습니다. 그림/그래프와 이미지 속 표는 원문 캡처 대조가 필요합니다.
- 기존 수동 수정본은 먼저 검토 저장으로 백업한 후 원본 PDF를 다시 분석하세요. 옛 검토 파일이나 문제함을 자동 덮어쓰지 않습니다.
- 현재 카탈로그는 2022 개정입니다. 2015 개정 시험의 기준과 동일하다는 뜻이 아니며 적합한 후보가 없으면 판단을 보류합니다.

캡처 이미지 내보내기 · 0.7.12 성취기준 매핑 추가
- ‘내보내기 → 캡처 이미지 구성’에서 기본값 ‘성취기준별 폴더 + 매핑 목록 · ZIP’을 선택하고 ‘성취기준별 캡처 · ZIP’을 누릅니다. 현재 성취기준 코드·교과별 폴더에 문항 캡처를 모으고, 미분류 문항도 별도 폴더로 보존합니다.
- ZIP 최상위 ‘문항목록.csv’에 이미지 경로·성취기준 코드와 내용·교과·원본 PDF 이름·문항 번호·캡처 순번·쪽수를 한 이미지당 한 행씩 기록합니다. 한글을 위해 UTF-8 BOM을 사용하며 수식처럼 실행될 수 있는 셀 앞에는 작은따옴표를 붙입니다.
- 현재 화면에서 선택된 매핑을 그대로 사용합니다. 내 문제함에서는 저장 당시 매핑을 사용하며 API로 새로 판독하거나 매핑하지 않습니다. 내보내기 전에 분류를 확인하세요.
- 기존처럼 이미지만 받으려면 ‘캡처 이미지 구성 → 이미지만 한 폴더 · ZIP → 캡처 이미지만 · ZIP’을 선택하세요. 이 모드는 성취기준·CSV 없이 이미지만 받습니다. DOCX/HWPX 파일 구성 선택과 별개입니다.
- 현재 문항 전체 캡처를 사용하며 그림만 자동으로 다시 자르는 기능은 아닙니다. 필요하면 먼저 ‘캡처 범위 수정’을 사용하세요.
- 일부 문항만 필요하면 ‘내 문제함’에서 여러 PDF의 문항을 고른 뒤 ‘선택 문항 내보내기’에서 같은 기능을 사용하세요.
- 파일명은 ‘선택 순번_PDF 이름_문항 번호_캡처 순번_원본 쪽수.jpg’ 형태입니다. JPG/PNG 원본 형식·화질을 그대로 보존합니다. 같은 번호도 덮어쓰지 않고, 여러 장인 문항은 각 캡처를 순서대로 모두 담습니다.
- 이미지에 매핑 글자를 덧붙이지 않습니다. 두 모드 모두 추출 문항 본문·DOCX/HWPX·원본 전체 페이지·API 키는 넣지 않습니다. 이미지를 다시 압축하거나 문항의 여러 캡처를 한 장으로 합치지 않으며 API도 호출하지 않습니다.
- 캡처가 없는 문항은 누락 안내 후 다운로드를 막습니다. 원본 PDF·검토 파일에서 캡처를 확인하거나 캡처가 있는 문항만 선택하세요. 캡처 범위 경고가 있는 문항도 현재 범위 그대로 포함됩니다.
- 한 번에 캡처 1,000장·이미지와 목록 데이터 합계 150MB까지 가능합니다. 더 큰 묶음은 나누어 선택하세요.
- 기존 검토 파일·문제함에서 사용할 수 있습니다. 캡처 이미지 자체에 문항 내용·개인정보가 포함되며 매핑 모드 CSV에도 원본 PDF 이름 등이 들어갑니다. 공유 전 확인하세요.

0.7.5부터 포함된 개선
- 중앙 문항 목록에도 자료·보기 박스와 표를 표시하며 굵게·밑줄·수식을 유지합니다. 긴 문항을 두 줄로 자르지 않습니다.
- 넓은 표와 수식은 가로로 스크롤해 끝까지 확인합니다. 문항 번호 버튼으로 선택하거나 내용을 클릭하면 오른쪽 정보가 바뀝니다.
- 표·수식 영역은 Tab 키로 이동해 방향키로 스크롤할 수 있습니다. 문항 번호 버튼은 Enter/Space로 선택합니다.
- 기존 검토 파일을 다시 열면 새 표시 방식이 적용됩니다. PDF 분석이나 API 판독을 다시 할 필요는 없습니다.

0.7.4부터 포함된 개선
- AI JSON에서 bigg/bar의 b가 백스페이스로, to/times/tilde의 t가 탭으로 변한 알려진 수식 손상을 복원합니다. 일반 본문의 탭과 표·cases의 줄바꿈은 유지합니다.
- lim 조건은 연산자 아래에 표시합니다. 수식 직후 줄바꿈과 중복 역슬래시를 보완합니다.
- 표시 불가능한 수식, 끊긴 첨자·절댓값, 전체 중복 발문을 검토 경고로 표시합니다. 잘못된 AI 결과가 정상 추출문을 덮어쓰지 않도록 보존합니다. 경고 없음은 의미 정확성의 보장이 아닙니다.
- 수동 수정본을 검토 저장한 뒤 옛 서버를 종료하고 새 ZIP을 별도 폴더에 모두 풀어 실행하세요. 검토 파일을 열면 알려진 이스케이프 손상이 복원되며 API 재호출은 필요 없습니다. 의미가 달라진 수식은 원문과 대조해 수정해야 합니다.

0.7.3부터 포함된 개선
- 중첩 지수, 극한·합의 위아래 범위, 근호·선분 윗줄·구간별 함수와 괄호 뒤 화학식 아래첨자를 보완했습니다.
- 병합 머리글은 하위 열마다 부모 제목을 유지합니다. 셀 안 빈칸 테두리는 표 열로 쓰지 않습니다. 별도 텍스트가 있는 이미지 테두리 메모도 일반 직사각형 표·상자로 복원합니다. 순수 이미지의 내용을 추측하는 기능은 아닙니다.
- 국어·수학은 공통 지문과 개별 발문을 구분해 평가 요소·교과 안에서 성취기준 후보를 추천합니다. 추천 근거를 확인하고 최종 기준을 선택하세요. 다른 과목은 기존 검색 방식입니다.
- 동일 코드 과다 사용·세트 내 반복은 검토 알림이지 오답 판정이 아닙니다. 공통 지문·개별 발문·검토 사유는 검토 파일과 문제함에 보존됩니다.
- 이 0.7.10 ZIP에도 위 수정이 포함되어 있습니다. 기존 ZIP은 자동 업데이트되지 않습니다. 원본 PDF를 다시 넣어야 새 PDF 추출이 적용됩니다. 기존 문제함·API 설정은 별도 데이터 폴더에 유지됩니다.

보안 안내
- 웹 서버는 외부 네트워크가 아닌 127.0.0.1에만 열립니다.
- Mac의 API 키는 macOS 키체인에 저장됩니다.
- Windows/Linux는 키를 암호화 파일에 보관하지만 복호화용 파일이 같은 폴더에 있어 키체인 수준의 보호는 아닙니다. 공용 PC에서는 사용 후 키를 지우세요.
- API 키 전체 값은 문항맵 화면에 다시 표시되지 않습니다.
- PDF 업로드의 로컬 추출은 API 키가 저장되어 있어도 AI 공급자에게 문항 자료를 보내지 않습니다.
- ‘이 문항만 API로 판독’ 또는 ‘전체 문항 API 판독’을 누르고 전송을 확인하면 대상 문항의 캡처 이미지와 텍스트가 해당 API 공급자에게 전송되며 비용이 발생할 수 있습니다.
- 표시되는 사용액과 잔액은 이 문항맵에서 관측한 토큰과 입력한 단가·예산으로 계산한 추정치입니다.
